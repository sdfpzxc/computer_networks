# Конспект по протоколу DHCP

## 1. Введение в DHCP

**Проблема:** Для работы сети каждому интерфейсу нужен IP-адрес. При ручной настройке администратор должен:
- Помнить, какие адреса заняты, а какие свободны
- Назначать не только IP, но и маску, шлюз, DNS-сервер, доменное имя
- Выполнять утомительную рутинную работу даже в небольших сетях

**Решение:** DHCP (Dynamic Host Configuration Protocol) — протокол динамического конфигурирования хостов.
- Автоматизирует настройку сетевых интерфейсов
- Централизованно управляет распределением адресов
- Гарантирует отсутствие дублирования адресов

---

## 2. Предшественники DHCP

### RARP (Reverse Address Resolution Protocol)
- Появился более 30 лет назад
- Принцип: клиент посылает широковещательный запрос → сервер находит привязку MAC→IP → отправляет IP-адрес
- **Недостатки:**
  - Сервер нужен в каждом сегменте сети
  - Ручная регистрация MAC-адресов
  - Нет передачи дополнительной информации

### BOOTP (Bootstrap Protocol)
- Создан на смену RARP
- Изначально для бездисковых станций
- Передавал: IP-адрес, адрес TFTP-сервера, имя загрузочного файла
- Поддерживал **relay** — сервисы пересылки запросов главному серверу
- Позволял использовать один сервер для нескольких сетей
- **Недостатки:** ручная настройка таблиц, ограничение размера доп. информации

### DHCP
- Совместимое расширение BOOTP
- DHCP-сервер поддерживает устаревших клиентов, но не наоборот

---

## 3. Режимы работы DHCP

DHCP работает по модели **клиент-сервер**. Клиент при старте посылает широковещательный запрос → сервер отвечает с IP и параметрами.

### Три режима:

| Режим | Описание |
|-------|----------|
| **Ручное назначение статических адресов** | Администратор вручную привязывает IP к MAC-адресу. Клиент всегда получает один и тот же адрес |
| **Автоматическое назначение статических адресов** | Сервер сам выбирает IP из пула при первом обращении и закрепляет его за клиентом навсегда |
| **Динамическое распределение** | IP выдаётся на ограниченное время (**срок аренды**). При уходе из подсети адрес освобождается и может быть выдан другому |

**Преимущество динамического режима:** позволяет строить сеть, где количество узлов превышает количество доступных IP-адресов.

### Пример эффективности
- 500 мобильных сотрудников, обычно в офисе ≤50
- Достаточно пула из 64 адресов и 64 рабочих мест
- Администратор один раз настраивает диапазон — клиенты получают параметры автоматически

## 4. Алгоритм динамического назначения адресов

### Управляемые параметры:
- **Пул адресов** — диапазон доступных IP
- **Срок аренды** — как долго клиент может использовать адрес (зависит от режима работы: от длительности лабораторной до нескольких недель)

### Схема обмена сообщениями:

1. **DHCP-поиск** — клиент посылает широковещательный запрос (IP-пакет с адресом назначения из одних единиц)
2. **Получение запроса** — DHCP-серверы или связной агент (relay) получают сообщение
3. **DHCP-предложение** — все серверы отправляют клиенту свои предложения (IP + конфигурация)
4. **DHCP-запрос** — клиент выбирает первое предложение и широковещательно запрашивает его
5. **DHCP-квитанция** — выбранный сервер подтверждает, остальные аннулируют предложения
6. **Рабочее состояние** — клиент получает адрес и параметры

### Обновление аренды:
- Клиент пытается обновить параметры задолго до истечения срока
- При неудаче — повторные попытки, затем обращение к другому серверу
- Если все отказывают — клиент теряет параметры и переходит в автономный режим
- Возможен досрочный отказ от параметров

### Роль relay-агента:
- Если в сети нет DHCP-сервера, его подменяет **связной DHCP-агент**
- Пересылает запросы клиентов серверу в другой сети
- Один сервер может обслуживать несколько сетей

## 5. Проблемы динамического назначения адресов

1. **DNS-преобразование** — сложно поддерживать соответствие имён и IP, если адреса меняются каждые 2 часа
   - Решение: статические адреса для серверов, динамические — для клиентов
   - Для больших сетей — динамическая DNS (согласование баз DHCP и DNS)

2. **Удалённое управление и мониторинг** — сложно собирать статистику по динамически меняющемуся IP
   - Решение: статические адреса для устройств, предоставляющих услуги

3. **Безопасность** — усложняется фильтрация пакетов по IP-адресам

### Кому назначают статические адреса:
- Маршрутизаторы
- Серверы
- Принтеры
- Другие сетевые устройства с неизменным местоположением

## Ключевые термины

| Термин | Значение |
|--------|----------|
| **DHCP** | Dynamic Host Configuration Protocol |
| **RARP** | Reverse Address Resolution Protocol |
| **BOOTP** | Bootstrap Protocol |
| **Relay-агент** | Посредник между клиентами и серверами DHCP |
| **Срок аренды** | Время, на которое выдаётся IP-адрес |
| **Пул адресов** | Диапазон доступных для распределения IP |
